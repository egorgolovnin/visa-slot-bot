# Сайт Easy Visa: SEO-стратегия, запуск и план на 90 дней

Сайт — статический (Astro), лежит в `site/` репозитория `visa-slot-bot`, хостинг Cloudflare Pages. Цель — приводить жителей Кипра из Google и AI-поиска в бота @Easyvisaforyoubot.

---

## 1. Исследование

**Ограничение.** Доступа к Ahrefs, Semrush, Wordstat и Search Console нет, поэтому объёмы запросов, сложность и позиции конкурентов не указаны. После запуска их нужно снять из Search Console (через 4–6 недель) и Keyword Planner.

**Аудитория.** Русскоязычные жители Кипра с ВНЖ (в основном граждане России, Украины, Беларуси, Казахстана), которым нужен шенген. Боль: пустые календари VFS, перекупщики слотов, непонятно, куда и как подавать с Кипра.

**Что показывает выдача (ручной анализ, октябрь 2026).**
- По общим запросам «виза Кипр», «шенген Кипр» выдача занята материалами *о визе на Кипр для россиян* (tonkosti.ru, kmp.ru, dtf.ru, rbc). Это другая аудитория, конкурировать там бессмысленно.
- Запросы про *шенген из Кипра* закрыты слабо: ветки форума awd.ru, блог cyprusbutterfly, единичные статьи. Нет русскоязычной таблицы «страна → где подавать на Кипре → сборы».
- Тема «нет слотов» закрыта общими статьями без привязки к Кипру: visamanager.ru (обзор ботов и автозаписи), visa-slot.com, emiratesguru.ru.
- Прямые конкуренты по услуге — перекупщики в Telegram и cases.visarea.travel. Сайтов с понятной ценой и оплатой после брони не видно.

**Вывод.** Ниша узкая, но конкуренция по кипрским запросам низкая. Строим тематический авторитет вокруг «шенген для жителей Кипра»: порядок подачи, страны и системы записи, сборы, слоты. Это же даёт шанс на цитирование в AI-ответах, потому что у нас единственные структурированные данные по Кипру со ссылками на первоисточники.

## 4. Стек и почему он

- **Astro 5, статическая сборка.** Каждая страница — готовый HTML: контент виден роботам и AI-краулерам без JS, LCP около 1,5 с на мобильном в лабораторном тесте. JS на странице один, около 2 КБ: UTM, cookie-согласие, клики.
- **Статьи в Markdown** (`src/content/gid/*.md`) с проверяемой схемой frontmatter: title, seoTitle, description, даты, источники, FAQ. Новая статья — новый файл, всё остальное (меню гида, перелинковка «Читайте также», Article schema, sitemap) собирается само.
- **Cloudflare Pages.** Бесплатно, CDN, HTTPS, не связан с VPS бота (IP бота не светится), домен и почта в одном аккаунте.
- **Факты в одном месте:** цены, шансы колеса, процент рефералки, страны — в `src/site.ts`. Поменяли в боте — поменяйте там.
- **Проверка сборки** (`scripts/check-build.mjs`) валит сборку при битых внутренних ссылках, отсутствии или дубле title и description, нескольких H1, сломанном JSON-LD и неверном формате deep link.

Дизайн: палитра из рекламных баннеров бота (тёмно-синий, зелёный «штамп», синий), шрифты Unbounded + Golos Text, шрифты размещены на самом сайте. Главный визуальный элемент — колесо, где размер сектора равен реальному шансу.

## 5. Колесо, рефералка, deep links

- Колесо и рефералка существуют только в боте. На сайте — схема с честными шансами (5% — 34, 10% — 30, 15% — 20, 20% — 12, 30% — 3, 100% — 1) и кнопки перехода. Никаких таймеров, «победителей» и фиктивного вращения.
- Бот доработан (коммит `03d2c74`): `?start=wheel-<метка>` сразу открывает колесо, `invite-<метка>` — реферальную ссылку, `order-<метка>` — заявку. Метка сохраняется как источник в /admin → Источники. Реферальные ссылки `ref<ID>` не изменились, сайт их не трогает.
- **Нужно выкатить на VPS:** `cd /root/visa-slot-bot && git pull && docker compose up -d --build bot`.
- Ссылки вида `https://t.me/Easyvisaforyoubot?start=...`. На телефоне открывают приложение Telegram, на компьютере — страницу t.me с кнопкой открытия в Telegram Desktop или Web. Проверено, что параметр доходит до бота в нужном формате (тесты бота).

## 6. Аналитика

**Что уже в коде.**
- GA4 подключается, только если задан `PUBLIC_GA_ID` и посетитель нажал «Разрешить» (аудитория в ЕС, нужен GDPR-consent).
- Событие `tg_click` на каждой кнопке бота с параметрами `cta_action` (wheel / invite / order / start), `cta_place` (например home_hero), `page_path`.
- UTM: `utm_source` первого захода сохраняется на сессию и дописывается к метке бота: `wheel-site_home_hero_tgads`. В /admin бота видно, с какой страницы и какой рекламы пришёл пользователь.

**Настроить в GA4.**
1. Admin → Data streams → Web, указать домен.
2. Events → отметить `tg_click` как **Key event**.
3. Custom definitions → event-scoped dimensions `cta_action` и `cta_place`.
4. Отчёт Explore: key event `tg_click` по `page_path` и `cta_place`, конверсия = tg_click / sessions.

**Важно.** Клик по кнопке — это не регистрация. Новых пользователей, заявки и оплаты по источникам смотрите в /admin бота (метка `site_*`). Сквозная воронка: GA4 «клики по страницам» → бот «новые пользователи с меткой site_*» → «заявки» → «оплаты».

**UTM для рекламы.** `?utm_source=tgads&utm_medium=cpc&utm_campaign=<название>`. Для сообщества: `utm_source=community`. В метку бота попадает только `utm_source` (до 12 латинских символов или цифр).

## 7. Домен

**Критерии:** коротко и легко продиктовать, без дефисов если возможно, бренд Easy Visa, `.com` или `.eu`, без слов VFS, embassy, official (риск путаницы с официальными сайтами и претензий), WHOIS скрыт.

**Варианты** (доступность проверить не удалось, из песочницы закрыт доступ к RDAP; проверьте в Cloudflare Registrar):
1. `easyvisacy.com` — коротко, бренд + Кипр.
2. `easyvisa-cyprus.com` — понятнее, но длиннее и с дефисом.
3. `easyvisa.eu` — красиво, но скорее всего занят. Для `.eu` нужен адрес в ЕС, он у вас есть.
4. `visaforyou.eu` — совпадает с названием бота «Visa for you».

Не берите `.cy`: регистрация требует кипрских данных, а в публичный реестр они попадают чаще.

**Анонимность.** Регистрируйте в Cloudflare Registrar, там WHOIS скрыт бесплатно. Используйте отдельный аккаунт Cloudflare на служебную почту. Помните, что Cloudflare Pages подключается к GitHub: репозиторий виден только вам, но аккаунт GitHub должен оставаться тем, что не связан публично с вашим именем, если анонимность критична.

## 8. Корпоративная почта

Рекомендация: **Zoho Mail** (бесплатный тариф на 1 домен, приём и отправка) или Google Workspace (платно). Только Cloudflare Email Routing принимает почту, но отправлять с него нельзя.

Адреса: `support@` (вопросы, указать на сайте в `PUBLIC_CONTACT_EMAIL`), `privacy@` (запросы по данным, можно алиасом на support), `no-reply@` (если бот когда-нибудь будет слать письма).

DNS-записи в Cloudflare (значения из панели Zoho, регион EU):

| Тип | Имя | Значение |
|---|---|---|
| MX | @ | `mx.zoho.eu` приоритет 10, `mx2.zoho.eu` 20, `mx3.zoho.eu` 50 |
| TXT (SPF) | @ | `v=spf1 include:zohomail.eu ~all` |
| TXT (DKIM) | `zmail._domainkey` | ключ из Zoho → Email Authentication → DKIM |
| TXT (DMARC) | `_dmarc` | `v=DMARC1; p=none; rua=mailto:dmarc@ваш-домен; adkim=s; aspf=s` |
| TXT | @ | `zoho-verification=...` (одноразово) |

Через 2–4 недели, когда отчёты DMARC чистые, поменяйте `p=none` на `p=quarantine`, а потом на `p=reject`. Это защита от писем «от вашего имени». MX-записи не проксируются (серое облако).

## 9. Публикация на Cloudflare Pages

1. Cloudflare → Workers & Pages → Create → Pages → Connect to Git → репозиторий `visa-slot-bot`.
2. Build settings: Framework preset **Astro**, Root directory **`site`**, Build command `npm run build`, Output `dist`.
3. Settings → Build → **Build watch paths**: include `site/*`. Тогда коммиты в код бота не пересобирают сайт.
4. Environment variables (Production):
   - `SITE_URL` = `https://ваш-домен` (без него сайт собирается с noindex и Disallow — это защита превью)
   - `NODE_VERSION` = `22`
   - `PUBLIC_GA_ID` = `G-XXXXXXX` (когда создадите GA4)
   - `PUBLIC_GSC_VERIFICATION` = код из Search Console (если подтверждаете мета-тегом)
   - `PUBLIC_CONTACT_EMAIL` = `support@ваш-домен` (когда заработает почта)
5. Custom domains → добавить `ваш-домен` и `www.ваш-домен`. Rules → Redirect Rules: `www` → апекс, 301. SSL/TLS → Always Use HTTPS.
6. Копия на `*.pages.dev` закрыта от индексации заголовком `X-Robots-Tag: noindex` (`public/_headers`).

## 10. Search Console

1. Добавьте ресурс **Доменный ресурс** (Domain property). Cloudflare умеет добавить TXT-запись автоматически.
2. Sitemaps → `sitemap-index.xml`.
3. URL Inspection → запросить индексацию главной, `/strany/`, `/gid/shengen-s-kipra/`, колеса и рефералки.
4. Через 1–2 недели: Pages → проверить, что важные страницы проиндексированы, нет «Duplicate without canonical».
5. Связать GSC и GA4 (Admin → Product links).

1. **GDPR.** Политика конфиденциальности должна называть, кто оператор данных (имя или компания и контакт). Сейчас там только поддержка бота, потому что сервис анонимный. Для паспортных данных граждан из ЕС это риск. Варианты: зарегистрировать компанию (например, кипрскую LTD) и указать её, или проконсультироваться с юристом. Я не юрист, это нужно решить вам.

## 12. Внешнее продвижение (безопасно)

- **Сообщества.** Полезный ответ со ссылкой на нужную статью в кипрских чатах, где обсуждают визы (с разрешения админов), а не рекламный спам.
- **Ресурс, на который хочется ссылаться.** Таблица `/strany/` и сборы по странам — уникальные данные по Кипру. Их можно предложить релокационным и экспатским каналам и блогам как справочник.
- **Экспертные материалы.** Колонки «Как записаться на шенген с Кипра в 2026» для русскоязычных кипрских медиа (с ссылкой на гид).
- **Кейсы.** Анонимная статистика по записям (страна, срок ожидания слота) из бота раз в квартал — оригинальные данные, которые цитируют и AI-ассистенты.
- **Обновление.** Сборы и порядок записи меняются — раз в месяц проверять `/strany/` и статью о сборах, обновлять дату.
- **Нельзя:** покупать ссылки пачками, PBN, каталоги, автокомментарии, сгенерированные статьи-однодневки.

AI-цитирование не гарантирует никто; повышает шансы то, что уже сделано: прямые ответы в начале статей, таблицы, источники, чистый HTML.
