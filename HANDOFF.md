# Easy Visa — передача проекта (HANDOFF)

Документ для того, кто принимает проект. Описывает, что это, как развёрнуто, как
устроен поиск слотов, как эксплуатировать и где границы системы.

---

## 1. Что это

`@Easyvisaforyoubot` («Easy Visa») — Telegram-бот, который **отслеживает появление
свободных слотов на запись на шенгенскую визу с Кипра** и мгновенно уведомляет.
Параллельно крутится статический сайт-витрина.

Бот **только ищет и уведомляет** о слотах. Он **не бронирует автоматически** — это
сознательное решение (см. §9).

Стек: Python 3.12, aiogram 3, asyncpg, Postgres 16, curl_cffi (TLS-отпечаток Chrome),
Astro + Caddy (сайт), Docker Compose. Код на GitHub, хостинг — собственный VPS.

## 2. Источники слотов (ключевое)

Три независимые системы записи, у каждой свой клиент и способ забора данных:

| Источник | Файл | Страны | Как берём | Ограничение |
|---|---|---|---|---|
| **VFS Global** (публичный) | `vfs.py` | Австрия, Венгрия, Словакия, Словения, Хорватия, Чехия, Финляндия, Швеция | POST `lift-api.vfsglobal.com/appointment/centerwithearliestslot`, без логина | Отдаёт **одну (самую раннюю) дату** на центр+категорию; данные — **кэш ~1 час** |
| **Посольство Германии** (RK-Termin) | `rktermin.py` | Германия + NL, BE, DK, NO, IS, LU (один общий календарь) | `service2.diplo.de/rktermin`, картинка-капча (локально `ddddocr`) | Капча на почти каждый запрос; слоты живут очень недолго |
| **Посольство Греции** (SuperSaaS) | `supersaas.py` | Греция + Мальта | `supersaas.com/schedule/EmbassyofGreeceinCyprus/VISA`, логин + арифметическая анти-бот капча | Сервер мягко банит всплески запросов (429) |

Франция/Испания/Италия в карточке бота указаны, но **не мониторятся** (их системы —
demarche.numerique, email, Prenot@mi).

### Как детектится слот
- Каждый фетч превращается в список `Slot(centre, category, earliest)`.
- `diff.py` сравнивает с прошлым состоянием (`current_slots`) → события `opened` /
  `earlier` / `later` / `closed`. Уведомляем по `opened` и `earlier`.
- **Германия (RK)** — исключение: забираем **все** свободные дни на 3 месяца и
  **каждую дату кодируем как отдельный слот** (дата в поле `category`), поэтому ловим
  любую новую дату, а не только самую раннюю; плюс читаем времена по каждому дню
  (кэш + довычитывание новых, `RK_TIME_BUDGET` стр./цикл) и алертим о **новых временах**
  на уже открытых днях.
- Для VFS новые даты позже текущей самой ранней **невидимы** — это предел публичного
  эндпоинта (лечится только авторизованным календарём, см. §9).
- Все события пишутся в `slot_events`, срез каждого опроса — в `observations`
  (для аналитики «как часто/когда/сколько держатся»).

## 3. Архитектура и деплой

### Сервисы (`docker-compose.yml`)
- **db** — Postgres 16 (том `pgdata`).
- **flaresolverr** — получение `cf_clearance` для авторизованного VFS (опционально).
- **bot** — основной процесс (`python -m app.main`). Код смонтирован томом
  `./app:/app/app` → изменения подхватываются без ребилда.
- **site** — Astro-сайт под Caddy (порты 80/443).

### Где крутится
Собственный VPS (`82.26.171.55`), пользователь `root`, каталог `~/visa-slot-bot`.

### Деплой
```bash
# обычное обновление кода (том смонтирован — ребилд не нужен):
cd ~/visa-slot-bot && git pull && docker compose restart bot

# если менял .env (restart НЕ перечитывает переменные):
docker compose up -d bot

# пересобрать сайт (напр. после смены SITE_URL):
docker compose up -d --build site
```
Разовые диагностические раннеры (читают свежий код с тома):
```bash
docker compose exec bot python -m app._rk_run        # Германия сейчас: дни/времена
docker compose exec bot python -m app._rk_run grc    # Греция сейчас
docker compose exec bot python -m app._probe_run aut # авторизованный VFS (Австрия) — диагностика
```

## 4. Эксплуатация / мониторинг (встроенное)

- **Быстрый цикл Германии** — отдельная задача, опрос ~каждые `RK_FAST_INTERVAL_SEC`+fetch
  (сейчас ~25-30с), независимо от 10-минутного VFS-цикла. При сбое прокси RK уходит на
  прямое соединение (diplo не закрыт Cloudflare по IP).
- **Сторож** (`watchdog`): алерт, если (а) весь цикл завис; (б) один источник молчит
  (Германия/Греция индивидуально, VFS — группой); (в) прокси не отвечает (пинг раз ~6 мин).
  Не поднимает ложную тревогу сразу после рестарта.
- **Канарейка** — независимый самотест парсера на маршруте, где слоты есть всегда
  (`CANARY_ROUTE`).
- **Недельная сводка** — раз в ISO-неделю статистика из `observations` админам.
- **Бэкап** — ежедневный дамп ключевых таблиц (`COPY`→`.tar.gz`) в админ-чат; вручную `/backup`.
- **Счётчик уловов** — в каждом алерте «Поймано слотов: страна — N, всего — M».
- Крэш-алерт + пинг при старте.

### Админ/диагностические команды (в боте)
`/health` — статус источников (последний успех, ошибки, свободные дни).
`/slots [дней]` — статистика по `observations`.
`/status`, `/history`, `/users`, `/user`, `/admin`, `/allow|/ban|/unban|/deny`,
`/broadcast`, `/post`, `/link`, `/panel`, `/backup`, `/discover`.
Диагностика VFS-авторизации: `/monprobe`, `/slotprobe`, `/calprobe`, `/vfslogin`,
`/capsolver`, `/rkform`.

## 6. Модель данных (ключевые таблицы)

- `users` — пользователи, доступ (`allowed`/`banned`/`blocked_bot`).
- `missions` — страны/источники: `offered`, `fetched_at` (последний успех), `last_error`.
- `current_slots` — текущее состояние слотов (ключ `mission, centre, category`).
- `slot_events` — лог событий (`opened/earlier/later/closed`, `new_date`, `at`) — **отсюда
  считается, как быстро разбирают слоты**.
- `observations` — срез каждого опроса (`available`, `earliest`, `n_dates`, `age_min`, `times`).
- `subscriptions` — подписки пользователей на страну+окно дат (рассылка подписчикам
  реализована в коде, но UI подписки в боте **не подключён** — см. §9).
- `orders`, `visa_cases`, `direct_payments`, `discounts`, `prices` — заявки/оплаты/скидки.
- `kv` — служебные флаги (даты бэкапа, недельной сводки, разовые миграции).

## 7. Карта модулей (`app/`)

- `main.py` — сборка процесса, запуск задач (poller, watchdog, canary, rk_fast_loop,
  payment_watcher, backup_watcher), глобальный обработчик ошибок.
- `poller.py` — оркестровка опроса, `_poll_mission`, медленный цикл + быстрый цикл RK,
  сторож, анти-флуд/бэкофф Греции, алерты, недельная сводка.
- `vfs.py` / `vfs_auth.py` / `vfs_browser.py` / `vfs_fields.py` — публичный VFS, логин,
  браузер (Camoufox), разведка полей формы.
- `rktermin.py` / `rk_book.py` — немецкий календарь + капча + разбор формы.
- `supersaas.py` — греческий календарь + арифметическая капча.
- `cf.py` / `capsolver.py` — Cloudflare clearance (FlareSolverr) и решение Turnstile.
- `diff.py` / `slotstats.py` — детект изменений и статистика.
- `bot.py` — команды, middleware, тексты карточки бота.
- `orders.py` / `promo.py` / `direct_pay.py` / `payments.py` / `gform.py` — заявки,
  колесо/скидки, оплаты (CryptoBot/USDT), приём веб-формы.
- `db.py` — схема и запросы. `web.py` — сайт/панель/вебхуки. `backup.py` — бэкап БД.
- `mailbox.py` — чтение OTP из почты. `security.py` / `sanitize.py` — доступ/санитайзинг.
- `_rk_run.py`, `_probe_run.py`, `slot_probe.py`, `checks.py` — диагностика.

## 8. Типовые проблемы (runbook)

- **VFS: всё `403`** → Cloudflare режет IP. Нужен резидентский `PROXY_URL`, затем `/discover`.
- **Германия краснеет с `over proxy … CONNECT tunnel 504`** → моргает прокси-провайдер;
  RK сам уходит на прямое соединение. Если постоянно — проверить баланс/доступ прокси.
- **Греция `429 Too many requests from this browser`** → SuperSaaS придушил всплеск;
  бот сам опрашивает её не чаще 30 мин и откатывается на 2 ч. **Руками `_rk_run grc`
  не гонять** — каждый тест = новый логин+капча, продлевает бан.
- **Авторизованный VFS `403102`** → это **app-layer** (запрос доходит до бэкенда VFS),
  логину нужен валидный Turnstile-токен; `429002`/«Repeated Delay» = VFS рейт-лимитит
  логины. Лечение: **логиниться редко** (кэш токена ~5.5ч), не долбить тестами, при
  жёсткой штрафной — второй **свой** VFS-аккаунт в `VFS_ACCOUNTS`.
- **«Источник молчит» 🔕** → смотри `/health`: последний успех и последнюю ошибку.

## 9. Границы и нереализованное (важно знать)

- **Автобронирование НЕ реализовано и не будет** в рамках этого проекта — сознательное
  решение владельца. Бот доводит до момента записи (ловит слот, шлёт алерт), запись
  человек делает сам.
- **Авторизованный реалтайм-календарь VFS** (минуя часовой кэш публичного эндпоинта) —
  не доведён: упирается в анти-абуз VFS на входе. Рабочий путь — **один-два собственных
  аккаунта** + редкий логин. Это единственный способ ловить «горячие» VFS-страны
  (Австрия и т.п.) быстрее кэша.
- **Рассылка подписчикам** (`db.subscribers` + `_notify_subscribers`) написана, но в боте
  **нет UI подписки**, поэтому пока не используется (бот работает по модели заявок).
- **Наблюдение по Германии:** слоты бывают очень короткими (зафиксирован случай жизни
  **<2 минут**). Быстрый цикл их ловит, но ручная запись в такое окно — на грани.

## 10. Быстрый старт для нового владельца

1. Получить доступ к GitHub-репозиторию и к VPS (`ssh root@<ip>`).
2. На VPS: `cd ~/visa-slot-bot`, проверить `.env` (ротировать секреты — §5).
3. `docker compose up -d` — поднять всё. Логи: `docker compose logs -f bot`.
4. В Telegram открыть бота, `/start`, затем `/health` — убедиться, что источники 🟢.
5. Обновления кода: `git pull && docker compose restart bot`.
